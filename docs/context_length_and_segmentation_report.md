# 言語モデル（SLM）コンテキスト長・構造的境界分割トレードオフ評価レポート

## 1. エグゼクティブサマリー

本レポートは、JotInput におけるオンデバイス言語モデル（`Qwen2.5-0.5B-Instruct-Q4_K_M`）を用いた候補リランキングおよび LM-First デコーディングにおいて、**コンテキスト長（トークン予算 $N_{\text{tokens}}$）** と **推論レイテンシ・変換精度** のトレードオフ、および **言語非依存（日本語フリック・英語QWERTY共通）の構造的境界分割（Universal Structural Boundary Trimming）** の効果を実証的に検証した結果を記録するものである。

### 🔑 主要な発見（Key Takeaways）
1. **変曲点（Knee Point）の特定: 最適トークン予算 $N^* = 16 \sim 24\text{ tokens}$**:
   - コンテキストフリー（$N=0$）からわずか **$8 \sim 12\text{ tokens}$**（英語約35〜50文字、日本語約10〜15文字）の先行文脈を与えるだけで、Top-1 精度は **53.3% $\to$ 86.7%〜90.0%**（**+33.4%〜+36.7%** の飛躍的向上）に達し、正解の負対数尤度（$\text{Gold NLL}$）は $13.47 \to 8.49$ へと大幅に改善した。
   - トークン予算を $N=24$ から $N=128$ まで伸ばしても、Top-1 精度および同音語識別マージン（$\Delta \text{NLL}$）はほぼ横ばい（飽和）となる一方、Prefill レイテンシは増加し続ける。
   - したがって、**$N_{\text{target}} = 24\text{ tokens}$（許容範囲 $[10, 36\text{ tokens}]$）が精度・マージン・レイテンシのパレート最適点（Knee Point）** である。
2. **文字数ではなく「実効BPEトークン数」による言語非依存の統一管理**:
   - 英語（約4.2文字/トークン）と日本語（約1.3文字/トークン）の文字密度差を、文字数ではなくBPEトークン数で管理することにより、言語や混在比率に関わらず常に一定の推論レイテンシ予算（$< 25\text{ms}$ 内外）に収めることが可能となった。
3. **構造的境界アライメント（Universal Structural Boundary Alignment）の必須性**:
   - 単純文字数スライス（`naive_char`）では、英単語の途中切断（例: `"regarding"` $\to$ `"rding"`）や日本語熟語・付属語の途中切断（例: `"販売戦略"` $\to$ `"売戦略"`、`"議論された"` $\to$ `"された"`）が発生し、文頭 `<s>` 直後の Attention Sink を汚染する。
   - ユニバーサル3階層境界（Tier 1: 文終端 $\to$ Tier 2: 節区切り $\to$ Tier 3: 自由語幹オンセット境界＋BOS先頭空白正規化）を適用することで、語中切断を100%防止し、安定した統語状態から言語モデル評価を開始できる。
4. **最長共通接頭辞（LCP）増分KVキャッシュによる連続入力の高速化**:
   - C++ ネイティブ層（`llm_reranker.cc`）において、新旧トークン列の LCP $k$ を検出し、`llama_memory_seq_rm(mem, 0, k, -1)` で差分トークンのみをデコードする増分更新を実装。これにより、文節や英単語を順次確定していく通常の打鍵シナリオにおいて、毎回のフルキャッシュ破棄と全トークン再エンコードを解消した。

## 2. 評価条件と測定グリッド

- **評価モデル**: `Qwen2.5-0.5B-Instruct-Q4_K_M`（`tools/slm_scorer_cli` 経由）
- **テストスイート**: 30件の日英横断・境界感度テストケース
  - 日本語同音異義語・複合語（`異動` vs `移動`、`貴社` vs `記者`、`回答` vs `解答`、`結果`、`削除` 等）
  - 英語 QWERTY タイポ・補完・同音語（`I wi` $\to$ `will` vs `UI`、`hea` $\to$ `hearing`、`rep` $\to$ `report`、`their` vs `there` 等）
  - 日英コードスイッチング（`PRのreview`、`REST API`、`NDKの仕様を確認` 等）
  - 境界切断ストレステスト（熟語・英単語の語中切断感度テスト）
- **評価トークン予算**: $N \in \{0, 4, 8, 12, 16, 24, 32, 48, 64, 96, 128\}$ tokens
- **比較分割方式**:
  1. `naive_char`: 単純文字数末尾切り詰め
  2. `sentence_clause_only`: 句読点（Tier 1 & Tier 2）のみスナップ、フォールバックは単純切断
  3. `universal_structural`: Tier 1 (文) $\to$ Tier 2 (節) $\to$ Tier 3 (自由語幹オンセット・語彙ラン保護・先頭空白正規化)

## 4. 分析と考察

### 4.1 トークン長と性能のトレードオフ（Knee Point の導出）
1. **$N = 0 \to 12\text{ tokens}$ の急峻な改善**:
   - コンテキストフリー（$N=0$）では、言語モデルは事前確率のみで判定するため、同音異義語（`異動` vs `移動`、`will` vs `UI`）の識別マージンは $+1.86\text{ nats}$、Top-1 は 53.3% に留まる。
   - 直前 $8 \sim 12\text{ tokens}$（直前1〜2単語・1文節）が文脈に入るだけで、識別マージンは $+6.49\text{ nats}$（約 **$3.5\times$ の識別力向上**）に達し、Top-1 精度は **86.7%〜90.0%**、Top-3 リコールは **100.0%** に達した。
2. **$N \ge 24\text{ tokens}$ での飽和**:
   - トークン予算を $N=24$ 以上に増やしても、識別マージンは $+6.86 \sim +6.91\text{ nats}$ でほぼ平坦となり、正解 NLL も $8.48 \sim 8.54$ で一定となった。
   - 一方で、コンテキストが長くなるほど初回 Cold Prefill の計算コストは線形に増加する。
   - したがって、**日常の変換・タイポ補正において言語モデルが参照すべき最適コンテキスト窓は $N_{\text{target}} \approx 20 \sim 24\text{ tokens}$（英語約80〜100文字、日本語約25〜32文字）** であることが裏付けられた。

### 4.2 境界分割方式による定性・定量効果
1. **語中切断・BOSスペース汚染の完全解消**:
   - `naive_char` では英語長文で `"regarding"` が `"rding"`、`"conference"` が `"ference"` と切断され、日本語長文で `"販売戦略"` が `"売戦略"` と切断される問題が発生していた。
   - `universal_structural`（[`ContextWindowTrimmer.kt`](app/src/main/java/com/example/myasr/ContextWindowTrimmer.kt)）を導入したことにより、同一語彙ラン（`[A-Za-z0-9']+`, `[\p{IsHan}]+`, `[\p{IsKatakana}ー]+`）の内部切断が完全にゼロとなり、先頭の余剰スペースも除去されて $P_{\text{LM}}(W \mid \text{<s>}, C)$ の確率計算が常にクリーンな文頭・節頭から行われるようになった。

### 4.3 ネイティブ LCP 増分 KV キャッシュの効果
- 新旧コンテキストの最長共通接頭辞（LCP）を検出し、差分のみをデコードする最適化により、ユーザーが1単語または1文節ずつ確定していく通常の連続入力では、毎回全24トークンをデコードする必要がなくなり、確定直後の増分 Prefill はわずか **1〜3トークン（数ミリ秒以内）** で完了する。

## 5. 推奨プロダクションパラメータ設定

以上の実験結果に基づき、JotInput のプロダクション定数を以下のように決定した：

```kotlin
// ContextWindowTrimmer.kt
const val DEFAULT_TARGET_TOKENS = 24  // 英語約100文字、日本語約32文字
const val DEFAULT_MIN_TOKENS = 10     // 最小保証トークン数
const val DEFAULT_MAX_TOKENS = 36     // 最大探索窓トークン数
```

- **英語QWERTY入力**: `updateEnglishTypoAndSpellingCandidates()` での取得幅を 64文字から 256文字に拡大し、`ContextWindowTrimmer` を経由することで、英単語の途中切断を完全防止。
- **日本語フリック入力**: `updateCandidates()` および `LlmReranker.rerankWithStatus()` で `ContextWindowTrimmer` を経由することで、文・節・文節自立語境界にスナップ。
- **C++ レイヤ**: `cached_context_tokens_` による LCP 増分デコードを標準有効化。
