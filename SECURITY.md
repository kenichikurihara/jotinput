# Security Policy

## Supported Versions

Only the current `0.1.x` release line is supported with security fixes.

| Version | Supported |
| :--- | :--- |
| `0.1.x` | :white_check_mark: Supported |
| `< 0.1.0` | :x: Not supported |

---

## Reporting a Vulnerability

**Please do NOT report security vulnerabilities through public GitHub Issues, Pull Requests, or Discussions.**

Instead, please report suspected vulnerabilities privately through **GitHub Private Vulnerability Reporting**:

- Navigate to the repository's **Security** tab -> **Advisories** -> **Report a vulnerability** (`https://github.com/kenichikurihara/jotinput/security/advisories/new`).

Please include as much of the following information as possible so the issue can be evaluated efficiently:

- Affected JotInput version (`versionName` / release tag or commit SHA) and APK origin (GitHub Release vs. self-built)
- Android OS version, ABI (`arm64-v8a` / `x86_64`), and device model
- Clear step-by-step reproduction instructions or a minimal proof of concept
- Potential security or privacy impact (e.g., unintended data exposure, intent hijacking, tampered model loading)

> **Maintainer Response Note**: JotInput is maintained by a solo developer on a best-effort basis and does not currently run a paid bug bounty program. Thank you for practicing coordinated disclosure while fixes are prepared.

## Security & Privacy Architecture

For full data-handling details, see [`PRIVACY.md`](PRIVACY.md). Key security controls in JotInput include:

- **100% On-Device Processing & Zero Telemetry**: Voice audio, typed text, clipboard paste previews, and custom dictionaries are processed locally on-device with no analytics, ad SDKs, or cloud telemetry.
- **No Cloud/ADB App Backup (`android:allowBackup="false"`)**: `AndroidManifest.xml` disables automatic backup so local user data such as `custom_dictionary.json` is not extracted via backup mechanisms.
- **Restricted Internal Components**: Internal management activities (such as `DictionaryActivity`) use `android:exported="false"`.
- **Debug vs. Release Self-Update Isolation**: `REQUEST_INSTALL_PACKAGES` is declared only in debug builds (`app/src/debug/AndroidManifest.xml`) and is excluded from Release builds (`!BuildConfig.DEBUG`).
- **HTTPS Model & Lexicon Downloads**: Optional neural models and dictionaries are fetched on demand exclusively over HTTPS from the upstream sources documented in [`PRIVACY.md`](PRIVACY.md).

## Verifying Official Release APKs

Official `v*` releases publish a signed Release APK (`jotinput-<version>-universal-release.apk`) and a checksum manifest (`SHA256SUMS.txt`) generated by GitHub Actions CI/CD.

1. Verify the SHA-256 digest:
   ```bash
   sha256sum -c SHA256SUMS.txt
   ```
2. Verify the APK signing certificate using Android SDK `apksigner`:
   ```bash
   apksigner verify --print-certs jotinput-0.1.0-universal-release.apk
   ```
   Confirm the package identifier is `io.github.kenichikurihara.jotinput` and that the signing certificate fingerprint matches across official `0.1.x` updates from this repository.
